# 패턴플로우 전시 모니터 (노트북 한 화면)

전시 노트북에서 도는 작은 프로그램과 그 화면이다. **패널 → Wi-Fi → FlowLocal → USB → 노트북 → Ableton Live → 스피커** 중 어디가 끊겼는지, 지금 무엇을 하면 되는지를 한국어로 보여 주고, 안 될 때는 **큰 버튼 하나(한 번에 다시 연결하기)로 차례로 다시 잇는다**. 폰 페이지는 없다. 이 노트북에서만 본다(`http://127.0.0.1:8765`, 다른 기기에서는 열리지 않는다).

- 모니터가 꺼져 있어도 전시(소리)는 돈다. 모니터는 보고, 버튼을 누를 때만 고친다. 하나 예외: **음악 프로그램(Ableton Live)이 꺼지면 모니터가 다시 켠다**(아래 "음악 프로그램 자동 다시 켜기", 운영자용 칸의 스위치로 끈다).
- 모니터가 FlowLocal에 저절로 보내는 것은 2초마다의 **상태 요청 하나뿐**이다. 그 밖의 신호는 사람이 버튼을 누를 때만 보낸다. **한 번에 다시 연결하기**는 한 번 누르면 그 한 번으로 필요한 것(다시 켜기, 패널 다시 켜기, 소리 다시 맞추기)을 차례로 보낸다.
- 모니터를 다시 켜도 기억하는 것(이 노트북의 FlowLocal이 새 펌웨어로 대답한 적이 있는지 등)은 `logs/state.json`에 있다.
- 나중에 원인을 찾을 수 있게 FlowLocal의 카운터(거절한 초대, 시간 초과, 열린 세션, 빠진 패킷, USB 다시 맺기), 무선 채널, **핫스팟에 붙고 연결까지 걸린 시간**을 숫자 그대로 `logs`에 남긴다(아래 "기록").

## 켜기

| 언제 | 할 일 |
|---|---|
| 평소 | 노트북을 켜면 저절로 켜진다(아래 "처음 한 번"을 해 두었을 때). 창이 없으면 바탕화면의 **패턴플로우 모니터**를 두 번 누른다. 바로가기를 만들지 않았으면 레포 맨 위의 `패턴플로우 모니터 열기.bat`를 두 번 누른다 |
| 창을 닫았을 때 | 같다. 모니터가 이미 돌고 있으면 창만 다시 열린다 |
| 창이 "모니터 프로그램이 꺼졌어요" | 바탕화면의 **패턴플로우 모니터**를 두 번 누른다. 1분 안에 화면이 저절로 돌아온다 |

`start_monitor.bat`이 하는 일: `pf_monitor.py`를 창 없이(pythonw) 켜고, 대답할 때까지 최대 20초 기다린 뒤 Edge 앱 창(탭·주소창 없음)으로 연다. Edge가 없으면 기본 브라우저로 연다. 바탕화면·시작 프로그램 바로가기와 레포 맨 위의 `패턴플로우 모니터 열기.bat`은 모두 이 파일을 부르기만 한다.

### 처음 한 번 (설치 때)

1. Python 3.11과 python-rtmidi: `python -m pip install python-rtmidi`
2. `tools/monitor/install_startup.bat`을 두 번 누른다. **시작 프로그램**과 **바탕화면**에 "패턴플로우 모니터" 바로가기를 만든다(다른 설정은 건드리지 않는다). 지우려면 `install_startup.bat -Remove`.
3. `config.json`을 메모장으로 열어 연락처, 패널 전원 켜는 곳, Live 복구 창의 버튼을 적는다. 저장하면 몇 초 뒤 화면에 나온다.

## 화면 보는 법

색은 늘 **아이콘과 글자**가 같이 붙는다.

| 표시 | 뜻 |
|---|---|
| 초록 ✓ **정상** | 할 일 없음. "가끔 확인할 것"만 본다 |
| 노랑 ⏱ **기다리는 중** | 켜지는 중이거나 다시 붙는 중. 아무것도 누르지 말고 기다린다 |
| 노랑 △ **확인 필요** | 전시는 돌지만 봐야 할 것이 있다(무선 나쁨, 절전 설정 등) |
| 빨강 ⊗ **문제** | 지금 고쳐야 한다. **지금 할 일** 1번부터 한다 |
| 회색 ? **모름** | 모니터가 알 수 없다(스피커 소리는 늘 직접 들어 본다) |

첫 화면에는 다섯 가지만 있다.

- **맨 위 안내**: 제목 한 줄과 **지금 할 일** 번호 목록. 목록 안의 `[한 번에 다시 연결하기]`를 누르면 그 버튼으로 간다. 사람이 손으로 할 일(패널 전원, RST, 폰 Wi-Fi 끄기)은 글로 적혀 있다. 문제가 여럿이면 가장 급한 것이 위에, 나머지는 "함께 확인할 것"에 있다.
- **한 번에 다시 연결하기**(오른쪽, 좁은 화면에서는 안내 아래): 큰 파란 버튼. 누르면 단계마다 ✓ / 진행 중… / ✗ 와 걸린 초가 붙는다(아래 "한 번에 다시 연결하기"). 무선이 나쁠 때만 그 아래에 **무선 채널 바꾸기** 버튼이 함께 나온다.
- **신호가 가는 길**: 일곱 칸 중 빨간 칸이 끊긴 곳이다. 점선 칸은 선(Wi-Fi, USB)이다.
- **노브를 돌려 보세요**: K1–K3 막대. 관람객이 노브를 돌리면 막대가 따라 움직이고 초록 **막대가 움직여요 — 이어져 있어요**가 뜬다. 움직이면 패널 → 작은 보드 → 노트북이 이어진 것이다.
- **연락처와 현장 메모**(`config.json`).

접힌 칸 두 개:

- **자세히 보기**: 카드(지금 그림, 마지막 패널 신호, 무선(신호 세기·채널·켤 때 채널 점수·늦음·빠진 패킷·몰림), 핫스팟에 붙은 기기 수, FlowLocal 켜진 시간), **신호 도착**, **최근 기록**.
  - **신호 도착**: 최근 15초 동안 노트북에 들어온 패널 신호가 막대 하나씩 찍힌다(오른쪽이 지금). 노브를 돌리면 막대가 고르게 이어져야 한다. **같은 노브의 신호가 가는 길에 잡혀 있다가 한꺼번에 오면** 빨간 막대 위에 **몰림 n개**가 붙는다(아래 "몰림"). 패널이 연결될 때·소리 다시 맞추기 때 한꺼번에 오는 묶음(그림 + K1–K3)은 정상이라 빨갛지 않다. 아래 줄에 1분 동안의 몰림 횟수, 마지막 몰림(어느 노브, 몇 개, 앞에 몇 ms 멈췄는지)과 FlowLocal이 잰 늦음(흔들림, 1분 최대)이 나온다.
  - **최근 기록**: 상태가 바뀔 때와 버튼을 누를 때마다 한 줄. 같은 내용이 `tools/monitor/logs/날짜.log`에도 쌓인다(파일에만 가는 줄도 있다, 아래 "기록").
- **운영자용 자세히 보기**(맨 아래): **개별 버튼 (담당자용)**, **무선 채널**(지금 채널, 정하는 방식 `chm`, 켤 때 점수 `cs`, 채널 버튼 두 개), 음악 프로그램 자동 다시 켜기 스위치와 기록, FlowLocal이 보낸 값 전부(켜진 이유 `rsn`·`bc`·`ur` 포함, 모르는 키도), 모니터의 기억(`state.json`), 카운터, 판정 기준값, 버튼 기록, 한 번에 다시 연결하기의 단계와 기다리는 시간, 노트북 전원 설정(전원 연결·배터리)과 고치는 파일.

## 한 번에 다시 연결하기

"다 꽂혀 있는데 안 될 때" 누르는 버튼이다. 한 번 누르면 아래를 **차례로** 하고, 단계마다 화면에 ✓(됐어요) / 진행 중… / ✗(안 됐어요)와 걸린 초가 붙는다. 보통 20–30초, 음악은 그동안에도 계속 나온다(소리가 패널을 따라가지 않을 뿐). 확인창이 한 번 뜬다.

| 단계 | 하는 일 | 기다리는 시간 (실측 → 여유) |
|---|---|---|
| 1 작은 보드가 대답하는지 | 포트가 없으면 → **사람: USB 꽂기**. 포트는 있는데 대답이 없으면 25초 기다린다(`flx-mon2`는 대답을 못 보내면 스스로 USB를 다시 맺고, 그래도 안 되면 다시 켠다: 약 9초, 약 21초). 그래도 없으면 → **사람: RST 한 번** | 모니터가 포트를 못 열면 10초 뒤 멈추고 "노트북 다시 시작" |
| 2 작은 보드 다시 켜기 | 명령 12를 보낸다. 모든 패널 연결이 끝나고, 핫스팟과 무선 채널을 새로 연다(채널 자동이면 가장 조용한 채널을 다시 고름). 켜진 지 40초 안의 보드는 방금 켜진 것이라 건너뛴다. 답(4초)도 포트 사라짐도 없고 상태 답은 계속 오면 한 번 더 보내고, 또 안 받으면 → **사람: RST** | USB 1.6–1.9초 → 새로 켜진 답 15초 안, 핫스팟 13.3초 → 30초 안(넘으면 → **사람: USB 뽑았다 꽂기**) |
| 3 패널 다시 연결 | 핫스팟에 패널이 붙고(`cl`≥1) 연결(`ps`≥1)이 생기기를 기다린다. 붙었는데 10초 넘게 연결이 없으면 명령 11(패널 다시 켜기). 기기가 2대 이상이면 → **사람: 폰 Wi-Fi 끄기**(그다음 명령 11). 패널이 핫스팟에 아예 안 오면, 또는 명령 11이 패널에 닿지 않으면 → **사람: 패널 전원 껐다 켜기** | 붙기 1–2초 → 25초 안, 연결 0.5–1초 → 10초 뒤 명령 11, 패널 다시 켜기 뒤 붙기 5–7초 + 연결 1–1.5초 → 30초 안 |
| 4 음악 프로그램 | 켜져 있으면 **소리 다시 맞추기**(`BF 77 7F`)를 한 번 보낸다. 꺼져 있으면 전시 세트를 연다(자동 다시 켜기와 같은 방법) → FlowLocal의 `rr`이 느는 것(Live 장치가 세트를 연 뒤 보내는 재동기화)으로 세트가 열린 것을 안다. 자동 다시 켜기 스위치가 꺼져 있으면(운영자가 일부러 닫음) 켜지 않고 → **사람: 음악 프로그램 켜기** | 90초 안 |
| 5 마지막 확인 | 상태 답이 새로 오고, 패널 연결이 있고, 패널 소식(`hd`)이 15초 안이고, 음악 프로그램이 켜져 있는지 | 12초 안(AppleMIDI 동기화가 10초마다) |

끝나는 모양은 둘 중 하나다.

- 초록 **다 됐어요 — 패널 노브를 돌려 막대가 움직이는지 보세요**. 그 아래 "노브를 돌려 보세요" 칸에서 막대가 움직이면 끝.
- 사람이 해야 할 일이 생기면 노란 칸에 **한 가지만** 크게 나온다(맨 위 안내도 "한 가지만 해 주세요: …"). 하고 나면 모니터가 그것을 알아채고(포트가 보임, 작은 보드가 새로 켜짐, 패널 연결이 새로 생김, 기기가 1대가 됨, 음악 프로그램이 뜸) **알아서 이어서 한다**. 같은 부탁이 두 번 필요하거나 5분 안에 알아채지 못하면 멈추고 빨간 칸에 **할 일 하나**(보통 담당자 연락, 또는 다시 누르기)를 적는다.

- 누르는 사람이 한 번 누른 것만으로 명령 12·11과 소리 다시 맞추기를 (각각 많아야 두 번) 보낸다. 누르지 않으면 아무것도 보내지 않는다. 진행 중에는 다시 누를 수 없고, 개별 버튼도 잠긴다(개별 버튼이 진행 중이면 이 버튼이 잠긴다). **그만하기**로 언제든 멈출 수 있다(이미 보낸 것은 되돌리지 않는다).
- 모니터가 시킨 다시 켜기와 사람이 누른 RST는 "스스로 다시 켜짐"이나 "계속 다시 켜짐"으로 세지 않는다.
- 모든 단계, 보낸 바이트, 사람에게 부탁한 것과 알아챈 것, 결과가 `logs`에 한 줄씩 남는다(`[reconnect]`).
- 왜 이렇게 하나: 2026-09-27 19:22–19:24에 연결은 있는데 패널 소식이 없던 때, **패널 연결 다시 잡기**는 다시 붙었지만 여전히 조용했고 **패널 다시 켜기**는 패널에 닿지 않았다("no connection to panel"). **RST**(= 작은 보드 다시 켜기)로 핫스팟이 새로 뜨자 패널이 새로 붙어 돌아왔다. 그래서 이 버튼은 작은 보드 다시 켜기부터 한다.

## 개별 버튼 (담당자용, 운영자용 칸)

보통은 **한 번에 다시 연결하기** 하나면 된다. 아래 버튼은 운영자용 칸에 있고, 담당자가 한 가지만 콕 집어 하고 싶을 때 쓴다. 판정이 권하는 개별 버튼에는 **추천** 표시가 붙는다. 한 번 누르면 **메시지 하나만** 보낸다. 누른 뒤에는 결과가 나올 때까지 다른 버튼(과 큰 버튼)이 잠긴다(보통 10–30초, 길어야 1분). 같은 버튼은 몇 초(다시 켜기는 15초, 채널 버튼은 둘이 함께 30초) 뒤에 다시 누를 수 있다.

| 버튼 | 언제 | 무슨 일이 생기나 | 확인창 |
|---|---|---|---|
| **소리 다시 맞추기** | 소리가 패널 그림과 다를 때 | 작은 보드가 패널의 지금 그림(PC)과 K1–K3 값을 Live에 다시 보낸다. 아무것도 끊기지 않는다. 예전 FlowLocal 펌웨어에서도 된다 | 없음 |
| **패널 연결 다시 잡기** | 패널은 연결돼 있다는데 소리가 패널을 따라오지 않을 때, "패널 신호가 끊겼어요" | 작은 보드가 패널과의 RTP 연결을 끊고, 패널이 곧바로 새로 붙는다(보통 10초 안). 패널 그림은 그대로다. 연결이 없을 때는 끊을 것이 없어 눌러지지 않는다 | 없음 |
| **패널 다시 켜기** | 패널이 핫스팟에 있는데 연결이 안 붙을 때, 위 버튼으로 안 될 때 | 작은 보드가 패널에게 다시 켜라고 한다(패널의 `/api/wifi/reboot`). 패널 그림이 잠깐 꺼졌다가 첫 그림부터 다시 시작하고 30초쯤 뒤 붙는다. 패널이 핫스팟에 없거나, 핫스팟 기기가 여러 대라 어느 것이 패널인지 모를 때는 눌러지지 않는다 | 있음 |
| **FlowLocal 다시 켜기** | 핫스팟이 꺼졌을 때, 무선이 계속 나쁠 때 | 작은 보드가 답한 뒤 다시 켜진다. 켜질 때 가장 조용한 무선 채널을 다시 고른다(채널 자동일 때). 음악은 계속 나오지만 30초쯤 소리가 패널을 따라가지 않는다. 작은 보드가 **대답을 멈췄을 때는 이 버튼도 닿지 않는다**(같은 USB로 간다): 그때는 보드의 RST 버튼 | 있음 |
| **무선 채널 바꾸기 (지금 N번 → 다음 M번)** | 폰 핫스팟을 끈 뒤에도 무선이 계속 나쁠 때. 무선이 나쁠 때는 첫 화면에도 나온다 | 명령 13으로 1·6·11 중 지금 채널 다음 것(1→6→11→1, 그 밖의 채널은 그 위의 첫 후보)을 **번호로** 보낸다. 작은 보드가 답하고, 고른 채널을 저장한 뒤 다시 켜진다(USB 2초쯤, 핫스팟 13초쯤, 패널은 그 뒤 2초쯤). 다시 켜져도 그 채널 그대로(`chm=manual`). 다시 켜진 뒤 채널이 바라던 번호인지 확인해서 알려 준다. **`flx-mon3`부터** | 있음 (15초쯤 멈춤) |

채널 버튼과 옛 펌웨어: 상태 답의 펌웨어 태그가 `flx-mon1`·`flx-mon2`이면 두 버튼은 눌러지지 않고 "새 FlowLocal 펌웨어(flx-mon3)가 필요해요"가 나온다(2026-09-29 이 노트북의 FlowLocal은 `flx-mon2`). `flx-mon3`이거나 `chm=manual`·`cs=` 키가 오면 된다고 본다. 태그로 알 수 없으면 눌러 보게 두고, 상태 답은 오는데 명령 13에만 답이 없으면 "예전 FlowLocal 펌웨어(flx-mon3 전)는 이 명령을 몰라요. 아무것도 바뀌지 않았어요"라고 하고 5분 동안 채널 버튼만 "손으로" 안내로 바꾼다(다른 버튼은 그대로).

2026-09-25 실측(새 패널·FlowLocal 펌웨어): **패널 연결 다시 잡기**는 답이 바로 오고 MIDI가 1.0초 뒤, **패널 다시 켜기**는 답 0.04초에 MIDI가 4.7초 뒤, **FlowLocal 다시 켜기**는 FlowLocal이 켜지고 약 14초 뒤(그중 12초는 핫스팟을 일부러 늦게 켜는 시간) 돌아왔다. 화면의 "보통 10초 안", "30초쯤"은 여유를 둔 안내다.

개별 버튼을 누른 뒤 버튼들 위 칸에 나오는 것(무선 채널 바꾸기를 첫 화면에서 눌렀으면 그 버튼 아래에도):

1. **보내는 중… → 작은 보드의 답을 기다리는 중…** (2초, 패널 다시 켜기는 6초 안에 답이 와야 한다)
2. 답이 오면 **다시 연결 중… 보통 10초 안에 붙어요** 같은 안내와 진행 막대. 이때 화면이 빨개지지 않는다(끊기는 것이 예정된 일이라서).
3. **됐어요**(초록, 걸린 시간) 또는 **안 됐어요**(빨강/노랑)와 **다음:** 할 일. 다음이 버튼이면 그 버튼으로 가는 표시가 붙는다.

작은 보드가 "못 해요"라고 답하면 이유가 한국어로 나온다(예: "핫스팟에 기기가 여러 대라 어느 것이 패널인지 몰라요" → 폰 Wi-Fi 끄기). "너무 빨리 눌렀어요", "앞의 요청이 아직 안 끝났어요", "아직 켜지는 중"처럼 잠깐 지나가는 이유는 **안 된 버튼으로 치지 않는다**. 패널에 닿지 않았거나 다시 붙지 않은 버튼만 5분 동안 다음 할 일에서 빠진다.

답이 아예 없을 때:

- 작은 보드가 **이 노트북에서 한 번도** 대답한 적이 없으면: **새 FlowLocal 펌웨어가 필요해요**. 버튼 아래에 **손으로:** 하는 방법이 나온다. 2026-09-25 전에 구운 FlowLocal 펌웨어(`flx-mon1` 전)가 이 경우다.
- 이 노트북에서 대답한 적이 있는 FlowLocal이(모니터를 다시 켜기 전이라도) 대답하지 않으면: **멈춘 것**이다. 빨강 **FlowLocal이 대답을 멈췄어요** → 보드의 **RST** 버튼 한 번(BOOT 말고) → 안 되면 같은 테이프 자리에 뽑았다 꽂기 → 담당자. 개별 버튼은 모두 같은 USB로 가서 멈춘 보드에 닿지 않으므로 잠긴다(한 번에 다시 연결하기는 눌러도 되지만, 25초 기다린 뒤 같은 RST를 부탁한다). 2026-09-25 21:03–21:19에 이랬다: FlowLocal(`flx-mon1`, 오후 내내 대답함)이 핫스팟은 켠 채 USB 쪽이 조용했고, 21:12에 다시 켠 모니터가 "예전 펌웨어로 보여요"라고 잘못 말했다. RST로 돌아왔다.
- 모니터는 "대답한 적 있음"을 `logs/state.json`에 적어 두고 다시 켜져도 읽는다. 이 파일이 없거나 망가졌으면(`state.json.bad`로 남기고 새로 만든다) `logs/*.log`의 "FlowLocal 상태를 받기 시작했어요 (펌웨어 …)" 줄에서 다시 찾는다. 지워도 된다.
- 상태 답은 계속 오는데 이 버튼에만 답이 없으면: 답이 오다가 사라진 것으로 보고, 30초 뒤에도 그대로면 한 번 더 누르라고 한다. 채널 버튼만은 다르다: 그때는 명령 13을 모르는 옛 펌웨어로 본다(위).

개별 버튼 추천에서 "패널 연결 다시 잡기"는 **연결이 있을 때만** 권한다. FlowLocal은 끊을 연결이 없으면 "no RTP session to end"로 거절하기 때문이다. 연결이 없고 패널이 핫스팟에 있으면 "패널 다시 켜기"를 권하되, 그 앞에 늘 **패널에 그림이 보이는지(전원)** 를 먼저 보게 한다. 전원이 빠진 패널은 FlowLocal 핫스팟 목록에 한동안 남아 있어서(새 FlowLocal 펌웨어 `flx-mon1`은 30초, `FL_EXHIBIT_AP_INACTIVE_S`. 예전 펌웨어는 ESP-IDF 기본 300초) "기기 1대"로 보이고, 그 패널에는 다시 켜기 명령이 닿지 않는다. 그래서 패널이 조용해진 뒤 FlowLocal이 연결을 시간 초과로 끝낸 경우(`to`가 늘었거나 끊기기 전 `hd`가 30초를 넘었음)는 "패널 연결을 기다리는 중"으로 기다리지 않고 바로 전원 확인부터 안내한다.

무선이 나쁠 때 작은 보드를 USB 연장선으로 떼어 높은 곳에 두거나 파란(USB 3.0) 포트를 피하는 것은 **담당자 일**이다. 스태프 안내는 폰 핫스팟 끄기, 무선 채널 바꾸기(또는 한 번에 다시 연결하기), 담당자에게 알리기까지다. 작은 보드의 RST를 누르거나 뽑았다 꽂는 것은 화면이 그러라고 할 때만, 같은 테이프 자리에서 한다. BOOT는 누르지 않는다(`STAFF_CARD.md`).

## 노트북 전원 설정 — `노트북 전시용 전원 설정.bat`

충전기가 빠져도 전시가 멈추지 않으려면 **전원 연결(AC)과 배터리(DC) 둘 다** 아래처럼 돼 있어야 한다. 모니터는 60초마다 `powercfg /qh SCHEME_CURRENT <하위 그룹 GUID> <설정 GUID>`(안 되면 `/q`)를 읽어, 하나라도 다르면 노랑 "노트북 절전 설정을 고쳐야 해요"를 띄운다. 값은 설명 글이 아니라 GUID와 "AC"/"DC"가 적힌 줄의 16진수로 읽어서 한국어 Windows에서도 된다. 이 컴퓨터에 없는 설정(덮개 없는 컴퓨터의 덮개 등)은 "확인 못 함"으로 두고 문제로 치지 않는다. 배터리가 없는 컴퓨터는 전원 연결 값만 본다.

| 설정 | 하위 그룹 / 설정 | 전시 값 | 이 노트북, 2026-09-25 밤 (AC / DC) |
|---|---|---|---|
| 절전(잠자기) | SUB_SLEEP / STANDBYIDLE | 0 = 안 함 | 0 / 0 |
| 최대 절전 | SUB_SLEEP / HIBERNATEIDLE | 0 = 안 함 | 0 / **18000초(5시간)** |
| 덮개를 닫을 때 | SUB_BUTTONS / LIDACTION (숨은 설정이라 `/qh`로만 보인다) | 0 = 아무것도 안 함 | **1 절전 / 1 절전** |
| USB 선택적 절전 | `2a737441…` / `48e6b7a6…` (이 노트북에는 별칭이 없다) | 0 = 사용 안 함 | 0 / 0 |
| PCI Express 링크 상태 전원 관리 | SUB_PCIEXPRESS / ASPM | 0 = 해제 | **2 최대 절전 / 2 최대 절전** |

**고치기**: 루트 폴더(레포 맨 위, `패턴플로우 모니터 열기.bat`이 있는 곳)의 **`노트북 전시용 전원 설정.bat`을 한 번 실행한다**(두 번 누르기). 지금 쓰는 전원 구성표의 위 다섯 가지를 전원 연결·배터리 둘 다 0으로 하고(`powercfg /setacvalueindex` / `/setdcvalueindex SCHEME_CURRENT <하위 그룹> <설정> 0`), `powercfg /setactive SCHEME_CURRENT`로 적용한 뒤 바뀐 값(모든 줄이 `0x00000000`이어야 한다)을 보여 주고 멈춘다. 화면 끄기 시간은 건드리지 않는다. 다시 실행해도 된다. 모니터 화면은 1분 안에 따라온다.

- **관리자 권한이 필요 없다.** 전원 구성표의 권한이 사용자(BU)에게 읽기·쓰기(`KRKW`)를 준다: 이 노트북에서 관리자 권한 없이 `powercfg /getsecuritydescriptor SCHEME_CURRENT`와 `ActionSetActive`가 둘 다 `(A;CI;KRKW;;;BU)`였다. Microsoft의 powercfg 문서도 관리자 권한은 `/systemsleepdiagnostics`·`/systempowerreport`에만 적는다. 어떤 컴퓨터에서 "액세스가 거부"가 나오면 파일을 오른쪽 클릭 → 관리자 권한으로 실행한다. `powercfg /hibernate off`(관리자 필요)는 쓰지 않는다. 시간 설정 0이면 최대 절전으로 넘어가지 않는다.
- 없는 설정은 `NOT CHANGED`로 알리고 넘어간다.
- USB 루트 허브의 "전원을 절약하기 위해 컴퓨터가 이 장치를 끌 수 있음" 해제는 장치 관리자에서 따로 한다(관리자 권한, `ableton/README.md` 7장).

## 음악 프로그램 자동 다시 켜기

2026-09-25 21:44에 Ableton Live(12.4.1)가 꺼진 채로 남았고, 모니터는 "꺼졌어요"만 알렸다. 이제는 모니터가 다시 켠다.

- **언제**: 이 모니터가 켜진 뒤 Live가 도는 것을 본 적이 있고, Live 프로세스가 사라지고 **8초 뒤에도 없을 때**(그 사이 누가 손으로 켰을 수 있다). Windows가 꺼지는 중(`GetSystemMetrics(SM_SHUTTINGDOWN)`)이면 켜지 않는다. 노트북을 켤 때 Live를 여는 것은 모니터가 아니다(시작 프로그램, `ableton/README.md` 7장. 이 노트북의 시작 프로그램에는 2026-09-25 현재 Live 바로가기가 없다).
- **어떻게**: `config.json`의 `live_set`(기본 `set Project/set.als`, 레포 맨 위 기준)을 파일 연결로 연다(`os.startfile`, 이 노트북의 `.als` = `Ableton.Live.AppLiveSuite.als.12`). 그게 안 되거나 켰는데 90초 안에 Live가 안 뜨면, 다음에는 Live가 돌던 실행 파일(예: `C:\ProgramData\Ableton\Live 12 Suite\Program\Ableton Live 12 Suite.exe`)에 세트를 넘겨 연다.
- **몇 번**: 15분에 3번까지. 넷째로 꺼지면 더 켜지 않고 빨강 **Live가 계속 꺼져요 — 담당자에게 연락해 주세요**. Live가 다시 돌면(손으로 켬, 노트북 다시 시작) 풀린다. 스위치를 껐다 켜도 15분 안의 횟수는 그대로다.
- **화면**: 꺼져서 켜는 동안 노랑 기다림 **음악 프로그램(Ableton Live)이 꺼져서 다시 켜는 중이에요… 1분쯤 걸려요**, 할 일은 "아무것도 누르지 말고 기다리기"와 복구 창에서 누를 버튼(`live_recovery_button`). 세트가 열린 것은 FlowLocal의 재동기화 요청 수(`rr`)가 느는 것으로 안다(Live 장치가 세트를 열고 0.5초 뒤 요청한다, 루트 `README.md` 3장. 소리 다시 맞추기 버튼을 누른 뒤에는 이것으로 치지 않는다). 확인하지 못하면 5분 동안 노랑 **음악 프로그램이 조금 전 다시 켜졌어요 — 소리가 나는지 봐 주세요**.
- **기록**: 꺼짐, Windows 충돌 기록, 다시 켬(15분 안에 몇 번째), 떴음, 세트 열림 또는 모름, 멈춤이 모두 `logs`에 한 줄씩 남는다. 충돌 기록은 Windows 응용 프로그램 로그의 1000(Application Error), 1002(Application Hang), 1001(Windows Error Reporting APPCRASH·AppHang) 중 "Ableton Live"가 적힌 것을 `wevtutil qe Application /f:xml`로 읽는다(이벤트 ID와 데이터 값만 읽어서 한국어 Windows에서도 된다. 출력은 OEM 코드페이지다). **기록 없이 꺼지기도 한다**: 21:44에는 아무 기록이 없었고, 21:50의 1001 APPCRASH(`rthdasio64.dll`, `c0000005`)는 16:17 충돌의 보고서(ReportId `dd12d02c…` = 16:17 Application Error의 IntegratorReportId)를 늦게 보낸 것이다. 그래서 1001은 1000·1002가 없을 때만 쓰고, 기록이 없어도 다시 켠다. 이날 Live는 15:52와 16:17에도 `rthdasio64.dll`(Realtek ASIO 드라이버)에서 죽었다.

### 스위치 — Live를 일부러 닫기 전에 끈다

운영자용 칸 맨 위의 **음악 프로그램(Ableton Live) 자동 다시 켜기** 스위치(= `config.json`의 `"live_autorestart"`. 모니터는 이 한 줄만 고쳐 쓰고 나머지는 그대로 둔다. config.json이 망가져 있으면 바꾸지 않는다). **켠 채로 Live를 닫으면 8초 뒤 다시 켜진다.** 세트를 고치려고 닫을 때는 먼저 끄고, 다 되면 다시 켠다. 꺼 두는 동안 Live가 꺼져 있으면 빨강 "음악 프로그램이 꺼져 있어요"(자세히: 자동 다시 켜기 꺼짐)가 나온다. 노트북을 끌 때(시작 → 전원 → 시스템 종료)는 그대로 둬도 된다 — 그래서 스태프 안내문의 끄는 순서는 Live를 따로 닫지 않고 바로 시스템 종료다.

### 복구 창 (crash recovery)

충돌 뒤 Live는 켜질 때 작업을 복구할지 묻는 창을 띄우고, 누가 누를 때까지 세트를 열지 않는다. 모니터는 이 창을 누르지 않는다. 화면은 `config.json`의 `live_recovery_button`(스태프 안내문의 같은 칸, 리허설에서 정한다)을 보여 준다.

창을 아예 안 띄우는 방법으로 Ableton 지원팀이 알려 준 Options.txt 한 줄이 있다: `-NoRestoreDocumentDialog`. 출처는 Ableton 포럼 스레드 "How to get rid of the 'Live unexpectedly quit while... Would you like to recover your work?' message?"(2023-06)에 옮겨진 지원팀 답이다("a fast start without prompts"). Ableton 도움말의 "Options.txt file" 페이지는 이번에 열리지 않아(403) 그 목록에 있는지는 확인하지 못했다. **모니터는 이것을 적용하지 않고, Live 설정 폴더를 건드리지 않는다.** 쓰기로 하면 운영자가 직접, 리허설에서:

1. 자동 다시 켜기 스위치를 끄고 Live를 닫는다.
2. `%APPDATA%\Ableton\Live 12.4.1\Preferences\`에 `Options.txt`를 만들고(메모장, 일반 텍스트) 한 줄 `-NoRestoreDocumentDialog`를 적어 저장한다. 이 노트북에는 2026-09-25 현재 어느 버전 폴더에도 Options.txt가 없다. Live 버전마다 폴더가 따로라, Live를 업데이트하면 새 버전 폴더에 다시 만든다.
3. Live를 켜서 세트가 열리는지 보고, 작업 관리자로 Live를 강제 종료한 뒤 다시 켤 때 복구 창 없이 세트가 열리는지 본다. 스위치를 다시 켠다.
4. 되돌리기: 그 줄(또는 파일)을 지운다.

이 줄을 쓰면 충돌 전의 저장 안 된 변경은 복구하지 않는다 — 전시에서는 저장된 전시 세트가 열리는 것이 맞다.

### PF monitor SysEx v1 (FlowLocal과의 약속)

제조사 ID `7D`(비상업용) + `50 46`("PF") + 명령. 글자는 0x20–0x7E, `key=value`를 `;`로 이음, 최대 240바이트. 모르는 키는 무시한다. FlowLocal 쪽 구현은 `flowlocal/src/fl_pf_monitor.h`, `fl_midi_bridge.h`.

| 방향 | 바이트 | 뜻 |
|---|---|---|
| 노트북 → FlowLocal | `F0 7D 50 46 01 F7` | 상태 요청 (2초마다) |
| 노트북 → FlowLocal | `F0 7D 50 46 10 52 43 F7` | 패널 연결 다시 잡기 ('R' 'C') |
| 노트북 → FlowLocal | `F0 7D 50 46 11 52 50 F7` | 패널 다시 켜기 ('R' 'P') |
| 노트북 → FlowLocal | `F0 7D 50 46 12 52 46 F7` | FlowLocal 다시 켜기 ('R' 'F') |
| 노트북 → FlowLocal | `F0 7D 50 46 13 43 48 <nn> F7` | `flx-mon3`: 무선 채널 ('C' 'H' 뒤에 값 한 바이트). `00` = 켤 때 자동으로 고르기, `01`–`0D` = 그 채널로 고정, `7F` = 1·6·11 중 지금 채널 다음 것. FlowLocal은 답하고, 고른 것을 저장하고, 다시 켜진다(USB 2초쯤, 핫스팟 13초쯤, 패널 2초쯤 뒤). 모니터는 "다음"을 `7F` 대신 **번호로** 보낸다(두 번 눌려도 한 채널만 넘어가게, 화면에 적힌 "다음 M번" 그대로) |
| 노트북 → FlowLocal | `BF 77 7F` | 소리 다시 맞추기 (재동기화 요청, Live 장치의 Resync와 같음) |
| FlowLocal → 노트북 | `F0 7D 50 46 02 <글자> F7` | 상태 답: `v fw up ap ch chm cl cm ps pip prs hd ra lp kn jt jm rx tx dr se to rj gp rr ud sr hi`, `flx-mon2`부터 `rsn`(마지막으로 켜진 이유: poweron, ext, sw, panic, int_wdt, task_wdt, wdt, deepsleep, brownout, sdio, usb, jtag, efuse, pwr_glitch, cpu_lockup, unknown), `bc`(전원을 넣은 뒤 켜진 횟수, 지금 켜진 것 포함), `why`(스스로 다시 켜기 전에 남긴 이유: cmd12, web, bridge_hung, usb_wedged, 없으면 빈 값), `ur`(켜진 뒤 USB를 스스로 다시 연결한 횟수). FlowLocal 쪽은 `flowlocal/src/fl_recovery.h`. `flx-mon3`부터 `chm`에 `manual`(명령 13으로 고른 채널)이 더해지고, `cs=1:<점수>,6:<점수>,11:<점수>`(마지막으로 켤 때 훑어본 채널 점수, 낮을수록 조용, 훑지 않았으면 빈 값). 모니터는 `cs`를 너그럽게 읽는다(읽히지 않는 조각은 건너뜀). 모르는 키는 판정에 쓰지 않는다(정수로 늘기만 하면 기록에 남긴다) |
| FlowLocal → 노트북 | `F0 7D 50 46 03 <글자> F7` | 명령 답: `cmd=<10\|11\|12\|13>;ok=<0\|1>;msg=<영어 짧게>` |

FlowLocal은 상태 답을 200 ms에 한 번까지만, 명령은 각각 3초에 한 번까지만 받는다. 명령 13은 SysEx 안쪽이 7바이트라 FlowLocal의 8바이트 받기 칸(`RX_MAX`)에 들어간다. `flx-mon2`는 모르는 길이의 SysEx를 버리고 답하지 않는다(모니터는 그것으로 "예전 펌웨어"를 안다). 글자가 240바이트를 넘으면 뒤쪽 키부터 빠진다(모니터는 빠진 키를 "모름"으로 본다). `flx-mon1`의 보통 답이 이미 190–200바이트이고 `flx-mon2`는 `rsn bc why ur`를 `hi` 뒤에 붙이므로, 카운터 자릿수가 늘면 이 네 키가 먼저 빠진다(모니터는 그때 켜진 이유를 "모름"으로 둔다). `flx-mon1`처럼 이 키들이 없으면 모니터는 켜진 이유를 "모름"으로 두고 알림을 띄우지 않는다.
