# Patternflow exhibition monitor (one screen on the laptop)

> **English translation.** The Korean original is [`README.md`](README.md). It was written for the crew of the 2026 exhibition *Anbu* in Seoul and describes that installation as it was — the exhibition laptop's paths, COM ports and dates are kept as facts. In this public copy the hotspot password reads `YOUR_HOTSPOT_PASSWORD`; the prebuilt firmware images, `flasher.html`, `backups/` and the project's copies of the audio samples are not included — build from source as the [full guide](../../docs/full-guide.en.md#build-it-step-by-step) shows. The original's `patternflow/` (the panel firmware clone) is what you get by applying [`firmware/panel-exhibit-2026.patch`](../../firmware/panel-exhibit-2026.patch) to Patternflow `4d264d5`, inside this repo; its `flowlocal/` (the FlowLocal firmware clone) is [`firmware/flowlocal/`](../../firmware/flowlocal/) here, so `flowlocal/EXHIBIT.md` means `firmware/flowlocal/EXHIBIT.md`. Where the original says "the root `README.md`", it means the Korean notes now in [`README.ko.md`](../../README.ko.md), translated in [`docs/setup-notes.en.md`](../../docs/setup-notes.en.md).

This is a small program that runs on the exhibition laptop, and its screen. It shows, in Korean, where the chain **panel → Wi-Fi → FlowLocal → USB → laptop → Ableton Live → speakers** is broken, and what to do right now. When something does not work, **one big button — 한 번에 다시 연결하기 ("Reconnect everything") — reconnects the links one after another**. There is no phone page. You look at it only on this laptop (`http://127.0.0.1:8765`; it does not open from other devices).

- The exhibition (the sound) keeps running even when the monitor is off. The monitor watches, and fixes things only when you press a button. One exception: **if the music program (Ableton Live) closes, the monitor starts it again** (see "[Automatic restart of the music program](#automatic-restart-of-the-music-program)" below; you turn this off with the switch in the operators' section).
- The only thing the monitor sends to FlowLocal on its own is **one status request every 2 seconds**. It sends any other signal only when a person presses a button. With **Reconnect everything**, a single press sends whatever is needed (a restart, a panel restart, a sound re-sync), one after another.
- What the monitor remembers across its own restarts (for example, whether this laptop's FlowLocal has ever answered with the new firmware) is in `logs/state.json`.
- So that the cause can be found later, it writes FlowLocal's counters (rejected invitations, timeouts, opened sessions, lost packets, USB re-attaches), the Wi-Fi channel and **the time from joining the hotspot to connecting** to `logs`, as raw numbers (see "[Log](#log--for-finding-the-cause-later)" below).

## Starting it

| When | What to do |
|---|---|
| Normally | It starts by itself when the laptop starts (once you have done "[Once, at install time](#once-at-install-time)" below). If there is no window, double-click **패턴플로우 모니터** ("Patternflow Monitor") on the desktop. If you never made that shortcut, double-click `패턴플로우 모니터 열기.bat` ("Open Patternflow Monitor") at the top of the repo |
| You closed the window | The same. If the monitor is already running, only the window opens again |
| The window says **모니터 프로그램이 꺼졌어요** ("The monitor program has stopped") | Double-click **Patternflow Monitor** on the desktop. The screen comes back by itself within 1 minute |

What `start_monitor.bat` does: it starts `pf_monitor.py` without a window (pythonw), waits up to 20 seconds for it to answer, then opens it in an Edge app window (no tabs, no address bar). Without Edge, it opens the default browser. The desktop and Startup shortcuts and `패턴플로우 모니터 열기.bat` ("Open Patternflow Monitor") at the top of the repo all just call this file.

### Once, at install time

1. Python 3.11 and python-rtmidi: `python -m pip install python-rtmidi`
2. Double-click `tools/monitor/install_startup.bat`. It makes a **패턴플로우 모니터** ("Patternflow Monitor") shortcut in **Startup** and on the **desktop** (it changes no other settings). To remove them: `install_startup.bat -Remove`.
3. Open `config.json` in Notepad and fill in the contacts, the place where the panel's power is switched on, and the button to press in Live's recovery dialog. When you save, it shows on the screen a few seconds later.

## Reading the screen

A color always comes with **an icon and words**.

| Shown | Meaning |
|---|---|
| Green ✓ **정상** ("OK") | Nothing to do. Look only at **가끔 확인할 것** ("Check now and then") |
| Yellow ⏱ **기다리는 중** ("Waiting") | Starting up or reconnecting. Press nothing and wait |
| Yellow △ **확인 필요** ("Needs a look") | The exhibition is running, but something needs a look (poor Wi-Fi, sleep settings, etc.) |
| Red ⊗ **문제** ("Problem") | Fix it now. Start with step 1 of **지금 할 일** ("What to do now") |
| Gray ? **모름** ("Unknown") | The monitor cannot know (always listen to the speakers yourself) |

The main screen has only five things.

- **The guide at the top**: a one-line headline and the numbered list **What to do now**. Pressing `[한 번에 다시 연결하기]` ("[Reconnect everything]") inside the list takes you to that button. Things a person must do by hand (panel power, RST, turning off phone Wi-Fi) are written out as text. If there are several problems, the most urgent one is on top and the rest are under **함께 확인할 것** ("Also check").
- **한 번에 다시 연결하기** ("Reconnect everything") (on the right; under the guide on a narrow screen): a big blue button. When you press it, each step gets ✓ / **진행 중…** ("In progress…") / ✗ and the number of seconds it took (see "[Reconnect everything](#reconnect-everything)" below). Only when Wi-Fi is poor, the **무선 채널 바꾸기** ("Change the Wi-Fi channel") button also appears under it.
- **신호가 가는 길** ("The signal's path"): of the seven boxes, a red box is where the chain is broken. Dashed boxes are the links (Wi-Fi, USB).
- **노브를 돌려 보세요** ("Try turning a knob"): bars for K1–K3. When a visitor turns a knob, its bar follows, and a green **막대가 움직여요 — 이어져 있어요** ("The bars are moving — it's connected") appears. If the bars move, panel → small board → laptop is connected.
- **연락처와 현장 메모** ("Contacts and site notes") (from `config.json`).

Two collapsed sections:

- **자세히 보기** ("Details"): cards (current pattern; last panel signal; Wi-Fi (signal strength, channel, channel scores at start-up, lateness, lost packets, bunching); number of devices on the hotspot; FlowLocal uptime), **신호 도착** ("Signal arrival") and **최근 기록** ("Recent log").
  - **Signal arrival**: each panel signal that reached the laptop in the last 15 seconds is drawn as one bar (the right edge is now). When you turn a knob, the bars should follow each other evenly. **When signals from the same knob were held up on the way and then arrive all at once**, a red bar gets **몰림 n개** ("n bunched") on top (see "Bunching" in "[Thresholds](#thresholds)" below). The burst that arrives when the panel connects or on a sound re-sync (pattern + K1–K3) is normal, so it is not red. The line below shows the number of bunchings in the last minute, the last bunching (which knob, how many signals, how many ms the knob had paused before it) and the lateness measured by FlowLocal (jitter, 1-minute maximum).
  - **Recent log**: one line whenever the state changes and whenever a button is pressed. The same lines also pile up in `tools/monitor/logs/<date>.log` (some lines go only to the file; see "[Log](#log--for-finding-the-cause-later)" below).
- **운영자용 자세히 보기** ("Details for operators") (at the very bottom): **개별 버튼 (담당자용)** ("Individual buttons (for the technician)"); **무선 채널** ("Wi-Fi channel") (the current channel, how it is chosen `chm`, the scores at start-up `cs`, the two channel buttons); the music program auto-restart switch and its log; every value FlowLocal sent (including the start reason `rsn`, `bc`, `ur`, and unknown keys too); the monitor's memory (`state.json`); counters; threshold values; the button log; the steps and waiting times of Reconnect everything; the laptop power settings (plugged in and on battery) and the file that fixes them.

## Reconnect everything

**한 번에 다시 연결하기** ("Reconnect everything") is the button you press "when everything is plugged in but it does not work". One press does the steps below **in order**, and on screen each step gets ✓ (**됐어요**, "Done") / **진행 중…** ("In progress…") / ✗ (**안 됐어요**, "Didn't work") and the number of seconds it took. It usually takes 20–30 seconds, and the music keeps playing the whole time (the sound just does not follow the panel). A confirmation dialog appears once.

| Step | What it does | Waiting time (measured → allowed) |
|---|---|---|
| 1 Is the small board answering? | If there is no port → **person: plug in the USB**. If the port is there but there is no answer, it waits 25 seconds (`flx-mon2`, when it cannot send its answer, re-attaches USB by itself, and if that does not help, restarts: after about 9 s and about 21 s). If there is still nothing → **person: press RST once** | If the monitor cannot open the port, it stops after 10 seconds and says "restart the laptop" |
| 2 Restart the small board | Sends command 12. Every panel connection ends, and the hotspot and the Wi-Fi channel are opened afresh (with the channel on auto, it picks the quietest channel again). A board that started less than 40 seconds ago has only just started, so this step is skipped. If there is no reply (4 s) and the port does not disappear, while status replies keep coming, it sends once more; if it gets nothing again → **person: RST** | USB 1.6–1.9 s → "just started" reply within 15 s; hotspot 13.3 s → within 30 s (longer → **person: unplug and replug the USB**) |
| 3 Reconnect the panel | Waits for the panel to join the hotspot (`cl`≥1) and for a connection (`ps`≥1). If the panel has joined but there is no connection for more than 10 seconds: command 11 (restart the panel). If there are 2 or more devices → **person: turn off phone Wi-Fi** (then command 11). If the panel never comes onto the hotspot, or command 11 does not reach the panel → **person: switch the panel power off and on** | Joining 1–2 s → within 25 s; connection 0.5–1 s → command 11 after 10 s; after a panel restart, joining 5–7 s + connection 1–1.5 s → within 30 s |
| 4 Music program | If it is running, sends **소리 다시 맞추기** ("Re-sync the sound") (`BF 77 7F`) once. If it is closed, opens the exhibition set (the same way as the automatic restart) → it knows the set has opened when FlowLocal's `rr` goes up (the resync the Live device sends after it opens the set). If the auto-restart switch is off (an operator closed Live on purpose), it does not start Live → **person: start the music program** | Within 90 s |
| 5 Final check | A new status reply has arrived, there is a panel connection, something was heard from the panel (`hd`) within the last 15 s, and the music program is running | Within 12 s (AppleMIDI sync comes every 10 s) |

It ends in one of two ways.

- Green **다 됐어요 — 패널 노브를 돌려 막대가 움직이는지 보세요** ("All done — turn a panel knob and see if the bars move"). If the bars move in the "Try turning a knob" box under it, you are finished.
- If a person has to do something, **just one thing** appears in large type in a yellow box (the guide at the top also says **한 가지만 해 주세요: …** ("Please do just one thing: …")). Once it is done, the monitor notices (the port appears, the small board has just started, a new panel connection appears, there is 1 device, the music program is up) and **carries on by itself**. If the same request is needed twice, or if it does not notice anything within 5 minutes, it stops and writes **one thing to do** in a red box (usually: contact the technician, or press again).

- A single press by a person sends commands 12 and 11 and the sound re-sync (each at most twice). If nobody presses, it sends nothing. While it is running, it cannot be pressed again, and the individual buttons are locked (while an individual button is in progress, this button is locked). You can stop it at any time with **그만하기** ("Stop") (what has already been sent is not undone).
- A restart ordered by the monitor and an RST pressed by a person do not count as "restarted by itself" or "keeps restarting".
- Every step, the bytes sent, what was asked of the person and what was noticed, and the result each leave one line in `logs` (`[reconnect]`).
- Why it works this way: on 2026-09-27 19:22–19:24, there was a connection but nothing was heard from the panel. **패널 연결 다시 잡기** ("Reconnect the panel") reconnected, but the panel stayed quiet, and **패널 다시 켜기** ("Restart the panel") did not reach the panel ("no connection to panel"). When **RST** (= restarting the small board) brought the hotspot up afresh, the panel joined again and came back. So this button starts by restarting the small board.

## Individual buttons (for the technician, in the operators' section)

Normally **한 번에 다시 연결하기** ("Reconnect everything") alone is enough. The buttons below are in the operators' section, for when the technician wants to do one specific thing. The individual button the diagnosis recommends carries a **추천** ("Recommended") tag. One press sends **only one message**. After you press, the other buttons (and the big button) are locked until the result comes (usually 10–30 seconds, at most 1 minute). You can press the same button again after a few seconds (15 seconds for the restarts; 30 seconds for the two channel buttons together).

| Button | When | What happens | Confirmation dialog |
|---|---|---|---|
| **소리 다시 맞추기** ("Re-sync the sound") | When the sound does not match the panel's pattern | The small board sends the panel's current pattern (PC) and the K1–K3 values to Live again. Nothing is disconnected. Works with older FlowLocal firmware too | None |
| **패널 연결 다시 잡기** ("Reconnect the panel") | When the panel is said to be connected but the sound does not follow the panel; **패널 신호가 끊겼어요** ("The panel signal has stopped") | The small board ends its RTP connection with the panel, and the panel rejoins right away (usually within 10 seconds). The panel's pattern stays as it is. When there is no connection, there is nothing to end, so it cannot be pressed | None |
| **패널 다시 켜기** ("Restart the panel") | When the panel is on the hotspot but the connection does not come up; when the button above did not help | The small board tells the panel to restart (the panel's `/api/wifi/reboot`). The panel's picture goes dark for a moment, starts again from the first pattern, and connects about 30 seconds later. It cannot be pressed when the panel is not on the hotspot, or when there are several devices on the hotspot and it cannot tell which one is the panel | Yes |
| **FlowLocal 다시 켜기** ("Restart FlowLocal") | When the hotspot is off; when Wi-Fi stays poor | The small board answers and then restarts. On start-up it picks the quietest Wi-Fi channel again (when the channel is on auto). The music keeps playing, but for about 30 seconds the sound does not follow the panel. When the small board **has stopped answering, this button cannot reach it either** (it goes over the same USB): then use the RST button on the board | Yes |
| **무선 채널 바꾸기 (지금 N번 → 다음 M번)** ("Change the Wi-Fi channel (now N → next M)") | When Wi-Fi stays poor even after phone hotspots are turned off. When Wi-Fi is poor, it also appears on the main screen | Command 13 sends, **as a number**, the channel after the current one among 1, 6 and 11 (1→6→11→1; any other channel goes to the first candidate above it). The small board answers, saves the chosen channel and restarts (USB after about 2 s, hotspot about 13 s, the panel about 2 s after that). After restarting it keeps that channel (`chm=manual`). After the restart, the monitor checks whether the channel is the number it wanted and tells you. **From `flx-mon3`** | Yes (about a 15-second pause) |
| **채널 자동으로** ("Channel back to auto") | When you want to stop using a hand-picked channel | Command 13 (value 0): goes back to looking around at every start-up and picking the quietest channel, and restarts. If it is already on auto, it cannot be pressed. **From `flx-mon3`** | Yes |

Channel buttons and old firmware: if the firmware tag in the status reply is `flx-mon1` or `flx-mon2`, the two buttons cannot be pressed and **새 FlowLocal 펌웨어(flx-mon3)가 필요해요** ("New FlowLocal firmware (flx-mon3) needed") appears (on 2026-09-29, this laptop's FlowLocal was `flx-mon2`). If the tag is `flx-mon3`, or if `chm=manual` or a `cs=` key arrives, the monitor assumes the buttons work. If it cannot tell from the tag, it lets you try. If status replies arrive but command 13 alone gets no reply, it says **예전 FlowLocal 펌웨어(flx-mon3 전)는 이 명령을 몰라요. 아무것도 바뀌지 않았어요** ("Older FlowLocal firmware (before flx-mon3) does not know this command. Nothing changed"), and for 5 minutes it turns only the channel buttons into "by hand" instructions (the other buttons stay as they are).

Measured on 2026-09-25 (new panel and FlowLocal firmware): **Reconnect the panel** got its reply at once and MIDI 1.0 s later; **Restart the panel** got its reply in 0.04 s and MIDI 4.7 s later; **Restart FlowLocal** was back about 14 s after FlowLocal started (12 s of that is the deliberate delay before the hotspot is started). The screen's **보통 10초 안** ("usually within 10 seconds") and **30초쯤** ("about 30 seconds") are guidance with a margin.

What appears in the box above the buttons after you press an individual button (and also under that button, if you pressed **Change the Wi-Fi channel** on the main screen):

1. **보내는 중… → 작은 보드의 답을 기다리는 중…** ("Sending… → Waiting for the small board's reply…") (the reply must come within 2 seconds; within 6 seconds for **Restart the panel**)
2. When the reply comes, guidance such as **다시 연결 중… 보통 10초 안에 붙어요** ("Reconnecting… usually connects within 10 seconds") and a progress bar. The screen does not turn red during this (the disconnection is expected).
3. **됐어요** ("Done") (green, with the time it took) or **안 됐어요** ("Didn't work") (red/yellow), and **다음:** ("Next:") with the next thing to do. If the next thing is a button, a mark that takes you to that button is attached.

If the small board answers "can't do it", the reason appears in Korean (e.g. **핫스팟에 기기가 여러 대라 어느 것이 패널인지 몰라요** ("There are several devices on the hotspot, so it can't tell which one is the panel") → turn off phone Wi-Fi). Passing reasons such as **너무 빨리 눌렀어요** ("Pressed too soon"), **앞의 요청이 아직 안 끝났어요** ("The previous request hasn't finished yet") and **아직 켜지는 중** ("Still starting up") **do not count as a failed button**. Only a button that did not reach the panel, or after which the panel did not reconnect, is left out of the next steps for 5 minutes.

When there is no reply at all:

- If the small board has **never once** answered **on this laptop**: **새 FlowLocal 펌웨어가 필요해요** ("New FlowLocal firmware needed"). Under the button, a **손으로:** ("By hand:") way of doing it appears. FlowLocal firmware flashed before 2026-09-25 (before `flx-mon1`) is this case.
- If a FlowLocal that has answered on this laptop (even before the monitor was restarted) does not answer: it has **stopped**. Red **FlowLocal이 대답을 멈췄어요** ("FlowLocal has stopped answering") → press the board's **RST** button once (not BOOT) → if that does not help, unplug it and plug it back in at the same taped spot → the technician. The individual buttons all go over the same USB and cannot reach a stopped board, so they are locked (you may press **Reconnect everything**, but after waiting 25 seconds it asks for the same RST). This happened on 2026-09-25 21:03–21:19: FlowLocal (`flx-mon1`, which had answered all afternoon) kept its hotspot on but went quiet on the USB side, and at 21:12 the restarted monitor wrongly said **예전 펌웨어로 보여요** ("Looks like older firmware"). RST brought it back.
- The monitor writes "has answered" in `logs/state.json` and reads it again after a restart. If this file is missing or broken (it keeps the broken one as `state.json.bad` and makes a new one), the monitor finds the fact again from the line **FlowLocal 상태를 받기 시작했어요 (펌웨어 …)** ("Started receiving FlowLocal status (firmware …)") in `logs/*.log`. You may delete the file.
- If status replies keep coming but this one button gets no reply: the monitor assumes a reply was coming and got lost, and if nothing changes within 30 seconds it asks you to press once more. The channel buttons alone are different: in that case it assumes old firmware that does not know command 13 (see above).

## Diagnosis rules (checked from the top; the most urgent one becomes the headline)

The to-do list on the main screen points only to things a person does by hand (panel power, cable, RST, phone Wi-Fi) and to **한 번에 다시 연결하기** ("Reconnect everything") (when Wi-Fi is poor, to **무선 채널 바꾸기**, "Change the Wi-Fi channel"). The individual button that is recommended carries a **추천** ("Recommended") tag in the operators' section (the "Individual:" part of the table below).

| Condition | Color | Headline | Main-screen button (Individual: recommended in the operators' section) |
|---|---|---|---|
| python-rtmidi is missing | Yellow | **모니터가 MIDI 신호를 읽을 수 없어요** ("The monitor can't read MIDI signals") | – |
| The monitor has just started | Waiting | **연결 상태를 확인하는 중이에요** ("Checking the connection status") | – |
| The "Patternflow Exhibit" port has just disappeared (within 6 s) | Waiting | **작은 보드를 다시 찾는 중이에요** ("Looking for the small board again") | – |
| No port | Red | **작은 보드(FlowLocal)가 노트북에 안 보여요** ("The small board (FlowLocal) isn't visible on the laptop") — check the taped spot, unplug and replug, restart the laptop | – |
| The port is there, but the monitor cannot open it | Yellow | **모니터가 FlowLocal 신호를 읽지 못하고 있어요** ("The monitor can't read FlowLocal's signals") | – |
| FlowLocal disappeared from the laptop and came back 3 times within 2 minutes (or restarted while the port stayed). Starts made with the restart buttons are not counted | Red | **FlowLocal이 계속 다시 켜지고 있어요** ("FlowLocal keeps restarting") — check the cable is pushed all the way in at the same taped spot, the laptop charger, contact the technician, (technician) `노트북 전시용 전원 설정.bat` ("Laptop power settings for the exhibition") | – |
| Within 10 minutes after the case above has ended | Yellow | **FlowLocal이 조금 전 여러 번 다시 켜졌어요** ("FlowLocal restarted several times a moment ago") — the same to-do | – |
| No reply for 6–20 s: replies that were coming have stopped, or a FlowLocal that has answered on this laptop does not send its first reply after the port is opened | Waiting | **작은 보드가 잠깐 대답하지 않아요** ("The small board isn't answering for a moment") | – |
| The same, but for more than 20 s | Red | **FlowLocal이 대답을 멈췄어요** ("FlowLocal has stopped answering") — RST once (not BOOT) → if that does not help, unplug, wait 5 s and plug in at the same taped spot → the technician | – (all individual buttons locked: they cannot reach a stopped board) |
| The same, but panel signals still reach the laptop meanwhile | Yellow | **FlowLocal이 모니터에 대답하지 않아요 — 패널 신호는 들어와요** ("FlowLocal isn't answering the monitor — panel signals are coming in") (if the sound is right, leave it; RST when there are few visitors) | – (locked) |
| A FlowLocal that has **never once** answered on this laptop gives no reply | Yellow | **FlowLocal 상태를 알 수 없어요 — 새 FlowLocal 펌웨어가 필요해요** ("FlowLocal's status is unknown — new FlowLocal firmware needed") (panel signals are still shown) | – |
| FlowLocal started less than 40 s ago; hotspot and panel not up yet | Waiting | **작은 보드가 켜지는 중이에요** ("The small board is starting up") | – |
| Hotspot off | Red | **FlowLocal 핫스팟이 꺼져 있어요** ("FlowLocal's hotspot is off") | Reconnect everything (Individual: **FlowLocal 다시 켜기**, "Restart FlowLocal") |
| No connection + hotspot full | Red | **핫스팟 자리가 꽉 찼어요** ("The hotspot is full") — turn off phone Wi-Fi | – |
| No connection + hotspot empty, less than 30 s since the connection dropped | Waiting | **패널이 다시 붙는 중이에요** ("The panel is rejoining") | – |
| No connection + hotspot empty | Red | **패널이 핫스팟에 없어요** ("The panel isn't on the hotspot") — check the panel power → if it is on and nothing changes after 1 minute, Reconnect everything → switch the power off and on | Reconnect everything (Individual: none — if the panel is not on the hotspot, **패널 다시 켜기** ("Restart the panel") cannot reach it) |
| No connection + a device present, within 25 s | Waiting | **패널 연결을 기다리는 중이에요** ("Waiting for the panel to connect") | – |
| No connection + 1 device, more than 25 s | Red | **패널이 핫스팟에는 있는데 신호 연결이 안 돼요** ("The panel is on the hotspot, but the signal connection doesn't come up") — check the panel power first | Reconnect everything, when a picture is showing on the panel (Individual: Restart the panel) |

Among the individual-button recommendations, **Reconnect the panel** is recommended **only when there is a connection**, because FlowLocal refuses with "no RTP session to end" when there is no connection to end. When there is no connection and the panel is on the hotspot, the monitor recommends **Restart the panel**, but always first has you check **whether a picture is showing on the panel (power)**. A panel whose power was pulled stays on FlowLocal's hotspot list for a while (30 s with the new FlowLocal firmware `flx-mon1`, `FL_EXHIBIT_AP_INACTIVE_S`; the ESP-IDF default of 300 s with older firmware), so it looks like "1 device", and a restart command cannot reach that panel. So when FlowLocal ended the connection with a timeout after the panel went quiet (`to` went up, or `hd` was over 30 s before the connection dropped), the monitor does not wait with "Waiting for the panel to connect" but goes straight to asking you to check the power.

When Wi-Fi is poor, moving the small board away on a USB extension cable and placing it up high, or avoiding the blue (USB 3.0) ports, is **the technician's job**. The staff instructions go only as far as turning off phone hotspots, Change the Wi-Fi channel (or Reconnect everything), and telling the technician. Pressing RST on the small board, or unplugging and replugging it, is done only when the screen says so, and at the same taped spot. Do not press BOOT ([`STAFF_CARD.en.md`](../../STAFF_CARD.en.md)).

### Thresholds

| Value | Threshold | Why |
|---|---|---|
| Status replies stopped | 6 s (red at 20 s) | The monitor asks every 2 s. Three missed replies in a row mean they have stopped |
| FlowLocal starting up | 40 s | After start-up, FlowLocal holds back its hotspot for 12 s, and the panel rejoins at 13–24 s (measured 2026-09-19) |
| Waiting for the panel connection | 25 s | The old panel image sent its first invitation 20–23 s after joining the hotspot (measured 2026-09-25). The new image of 2026-09-25 invites after 1 s, so it usually connects within a few seconds |
| Rejoining after a drop | 30 s | 8.5 s for the panel to notice the drop, then a few seconds to rejoin |
| Nothing heard from the panel | 30 s | AppleMIDI sync comes every 10 s. Three missed means the panel has dropped |
| Poor Wi-Fi | One of jitter, 1-minute maximum lateness, lost packets or bunching, below | Only signs that signals **really arrived late** are counted. A weak signal strength alone is not yellow (it shows as **약함** ("weak") on the Wi-Fi card, and is listed as a reason when it comes together with other signs) |
| Signal strength (prs) | Weaker than −75 dBm (only noted alongside) | Weaker than this, retransmissions increase, and signals tend to arrive late and bunched. If they still do not arrive late, it is no problem for the exhibition |
| Jitter (jt) | 20 ms or more | RFC 3550 jitter. A few ms on a quiet channel |
| 1-minute maximum lateness (jm) | 250 ms or more | The point at which you can hear the sound following the knob late. Not checked for 60 s after connecting (that minute contains the start of the connection) |
| Lost packets (gp) | 3 or more per minute | RTP packets lost over Wi-Fi |
| Bunching | 3 or more times per minute | **Bunching = two signals from the same knob (K1, K2, K3 = CC 24, 25, 26 on channel 1) arriving within 12 ms.** The panel sends at most one signal per knob every 50 ms, so if two from the same knob arrived within 12 ms, the first one was held up on the way for more than 38 ms and then released together with the second. Further pairs within the next 60 ms count as the same single bunching (on screen it is shown with the time that knob had paused before the bunching, like **K1·K2 신호 6개가 한꺼번에 (앞에 588 ms 멈춤)** ("6 K1·K2 signals at once (588 ms pause before)")). **Not counted**: bursts with one signal per knob (pattern + K1–K3, which the panel sends again every time it connects; FlowLocal's CC 118 mirror; the answer to a sound re-sync; the resend when USB re-attaches); each knob's first signal within 10 ms after a pattern change (PC) (that is FlowLocal resending the values it kept); a value equal to the one just before (a resend, not a turn); the on/off pairs of footstep notes; other CCs. When the driver's arrival times look broken (5 times in 1 minute), the monitor measures with **the time it read the message** instead, and then a short pause of the monitor itself also looks like bunching. So in that case bunching alone does not make the screen yellow; it is counted only when FlowLocal's values (jitter, lateness, lost packets) are bad too |
| Right after connecting | 20 s after connecting | During this time the Wi-Fi values are not used for diagnosis, and **bunchings and lost packets from those 20 s are not counted after the 20 s either**. Before, as soon as 20 s had passed, everything within the last minute was counted: the "poor Wi-Fi" at 2026-09-26 00:24:13 came 21 s after connecting and counted the normal burst before it (pattern + K1–K3) as bunching (00:22:56 was the same burst). On the signal-arrival line these show red, with **연결 직후 n번은 세지 않아요** ("n right after connecting not counted") |
| Slow connection (log only) | More than 8 s from joining the hotspot (`cl` 0→n) to connecting (`ps` 0→n) | Usually 1–2 s. On 2026-09-27 it took 20–24 s. Above the threshold, it is logged as a warning (±2 s, since status replies come every 2 s) |
| FlowLocal keeps restarting | 3 times in 2 minutes (yellow for 10 minutes after) | On 2026-09-25 at 21:02, a FlowLocal that had been plugged back in started four times within one minute (21:02:56, 21:03:26/32, 21:03:51/52) |
| "FlowLocal restarted by itself" alert | For 30 minutes after it started | After that, it remains only in the log (`logs`) and in `rsn` and `bc` in the operators' section. The same restart is written to the log only once, even if the monitor restarts (`state.json`) |
| Battery | Red below 30 % | Above that the sound does not stop, so a calm yellow |
| Music program restart | 8 s after it closes, up to 3 times in 15 minutes | 8 s: filters out someone restarting it by hand, or tasklist briefly missing it. If Live does not come up within 90 s of starting, one more try (via the executable); after it comes up, 60 s are allowed for opening the set |

## Laptop power settings — `노트북 전시용 전원 설정.bat`

So that the exhibition does not stop even when the charger is pulled out, **both plugged in (AC) and on battery (DC)** must be set as below. Every 60 seconds, the monitor reads `powercfg /qh SCHEME_CURRENT <subgroup GUID> <setting GUID>` (if that fails, `/q`), and if any one setting differs, it shows a yellow **노트북 절전 설정을 고쳐야 해요** ("The laptop's sleep settings need fixing"). It reads the values not from the description text but as the hex numbers on the lines with the GUID and "AC"/"DC", so it also works on Korean Windows. A setting this computer does not have (such as the lid on a computer without one) is left as **확인 못 함** ("Couldn't check") and is not counted as a problem. On a computer without a battery, only the plugged-in values are checked.

| Setting | Subgroup / setting | Exhibition value | This laptop, night of 2026-09-25 (AC / DC) |
|---|---|---|---|
| Sleep | SUB_SLEEP / STANDBYIDLE | 0 = never | 0 / 0 |
| Hibernate | SUB_SLEEP / HIBERNATEIDLE | 0 = never | 0 / **18000 s (5 hours)** |
| Lid close action | SUB_BUTTONS / LIDACTION (a hidden setting; visible only with `/qh`) | 0 = do nothing | **1 sleep / 1 sleep** |
| USB selective suspend | `2a737441…` / `48e6b7a6…` (this laptop has no alias for it) | 0 = disabled | 0 / 0 |
| PCI Express Link State Power Management | SUB_PCIEXPRESS / ASPM | 0 = off | **2 maximum power savings / 2 maximum power savings** |

**To fix it**: in the root folder (the top of the repo, where `패턴플로우 모니터 열기.bat` ("Open Patternflow Monitor") is), **run `노트북 전시용 전원 설정.bat` ("Laptop power settings for the exhibition") once** (double-click it). It sets the five settings above to 0 in the current power plan, for both plugged in and on battery (`powercfg /setacvalueindex` / `/setdcvalueindex SCHEME_CURRENT <subgroup> <setting> 0`), applies them with `powercfg /setactive SCHEME_CURRENT`, then shows the changed values (every line must be `0x00000000`) and pauses. It does not touch the display-off time. You may run it again. The monitor screen catches up within 1 minute.

- **No administrator rights are needed.** The power plan's permissions give users (BU) read and write (`KRKW`): on this laptop, without administrator rights, `powercfg /getsecuritydescriptor SCHEME_CURRENT` and `ActionSetActive` both returned `(A;CI;KRKW;;;BU)`. Microsoft's powercfg documentation also mentions administrator rights only for `/systemsleepdiagnostics` and `/systempowerreport`. If some computer says "Access is denied", right-click the file → Run as administrator. The file does not use `powercfg /hibernate off` (which needs administrator rights). With a timeout of 0, the laptop never goes into hibernation.
- Settings that do not exist are reported as `NOT CHANGED` and skipped.
- Unticking "Allow the computer to turn off this device to save power" on the USB root hubs is done separately in Device Manager (administrator rights; [`ableton/README.en.md`](../../ableton/README.en.md) §7).

## Automatic restart of the music program

On 2026-09-25 at 21:44, Ableton Live (12.4.1) closed and stayed closed, and the monitor only reported that it was closed. Now the monitor starts it again.

- **When**: the monitor has seen Live running since the monitor started, and the Live process has disappeared and **is still gone 8 seconds later** (someone may have started it by hand in the meantime). If Windows is shutting down (`GetSystemMetrics(SM_SHUTTINGDOWN)`), it does not start Live. Opening Live when the laptop starts is not the monitor's job (Startup folder, [`ableton/README.en.md`](../../ableton/README.en.md) §7; as of 2026-09-25 this laptop's Startup folder has no Live shortcut).
- **How**: it opens `live_set` from `config.json` (default `set Project/set.als`, relative to the top of the repo) through the file association (`os.startfile`; on this laptop `.als` = `Ableton.Live.AppLiveSuite.als.12`). If that fails, or if Live does not come up within 90 s after starting it, the next try hands the set to the executable Live was running from (e.g. `C:\ProgramData\Ableton\Live 12 Suite\Program\Ableton Live 12 Suite.exe`).
- **How often**: up to 3 times in 15 minutes. If Live closes a fourth time, the monitor does not start it again and shows a red **Live가 계속 꺼져요 — 담당자에게 연락해 주세요** ("Live keeps closing — please contact the technician"). This clears once Live is running again (started by hand, or after a laptop restart). Turning the switch off and on does not reset the count within the 15 minutes.
- **Screen**: while Live is being started after it closed, a yellow waiting state **음악 프로그램(Ableton Live)이 꺼져서 다시 켜는 중이에요… 1분쯤 걸려요** ("The music program (Ableton Live) closed, so it's being started again… takes about 1 minute"); the to-do is "press nothing and wait" and the button to press in the recovery dialog (`live_recovery_button`). The monitor knows the set has opened when FlowLocal's resync request count (`rr`) goes up (the Live device sends the request 0.5 s after it opens the set; see [§6 of the setup notes](../../docs/setup-notes.en.md#6-ableton-live) (the original says §3). After the **소리 다시 맞추기** ("Re-sync the sound") button has been pressed, this does not count). If it cannot confirm this, it shows yellow for 5 minutes: **음악 프로그램이 조금 전 다시 켜졌어요 — 소리가 나는지 봐 주세요** ("The music program restarted a moment ago — please check there is sound").
- **Log**: closed, Windows crash record, restarted (which time within the 15 minutes), came up, set opened or unknown, gave up — each leaves one line in `logs`. Crash records are read with `wevtutil qe Application /f:xml` from the Windows Application log: events 1000 (Application Error), 1002 (Application Hang) and 1001 (Windows Error Reporting APPCRASH, AppHang) that mention "Ableton Live" (it reads only the event IDs and data values, so it also works on Korean Windows; the output is in the OEM code page). **Live can also close without any record**: at 21:44 there was no record at all, and the 1001 APPCRASH at 21:50 (`rthdasio64.dll`, `c0000005`) was a late-sent report of the 16:17 crash (ReportId `dd12d02c…` = the IntegratorReportId of the 16:17 Application Error). So 1001 is used only when there is no 1000 or 1002, and Live is restarted even when there is no record. That day, Live had also died in `rthdasio64.dll` (the Realtek ASIO driver) at 15:52 and at 16:17.

### The switch — turn it off before you close Live on purpose

The switch **음악 프로그램(Ableton Live) 자동 다시 켜기** ("Music program (Ableton Live) auto-restart") is at the top of the operators' section (= `"live_autorestart"` in `config.json`; the monitor rewrites only this one line and leaves the rest as it is; if config.json is broken, it does not change it). **If you close Live while it is on, Live starts again 8 seconds later.** When you close Live to edit the set, turn the switch off first, and turn it back on when you are done. While it is off and Live is closed, a red **음악 프로그램(Ableton Live)이 꺼져 있어요** ("The music program (Ableton Live) is closed") appears (details: auto-restart off). When you shut down the laptop (Start → Power → Shut down), you can leave the switch as it is — that is why the closing order on the [staff card](../../STAFF_CARD.en.md) goes straight to Shut down without closing Live separately.

### The recovery dialog (crash recovery)

After a crash, Live shows a dialog on start-up asking whether to recover your work, and it does not open the set until someone presses a button. The monitor does not press this dialog. The screen shows `live_recovery_button` from `config.json` (the same blank as on the staff card, decided at the rehearsal).

There is an Options.txt line that Ableton support suggested for never showing the dialog: `-NoRestoreDocumentDialog`. The source is a support answer quoted in the Ableton forum thread "How to get rid of the 'Live unexpectedly quit while... Would you like to recover your work?' message?" (2023-06) ("a fast start without prompts"). Ableton's help page "Options.txt file" did not open this time (403), so it was not confirmed whether the line is on that list. **The monitor does not apply this, and it does not touch Live's preferences folder.** If you decide to use it, an operator does it by hand, at the rehearsal:

1. Turn off the auto-restart switch and close Live.
2. In `%APPDATA%\Ableton\Live 12.4.1\Preferences\`, create `Options.txt` (in Notepad, as plain text) with the single line `-NoRestoreDocumentDialog`, and save it. As of 2026-09-25, this laptop has no Options.txt in any version folder. Each Live version has its own folder, so after updating Live, create it again in the new version's folder.
3. Start Live and check that the set opens; then force-quit Live with Task Manager, start it again and check that the set opens without the recovery dialog. Turn the switch back on.
4. To undo: delete that line (or the file).

With this line, unsaved changes from before a crash are not recovered — for the exhibition, opening the saved exhibition set is the right thing.

### PF monitor SysEx v1 (the contract with FlowLocal)

Manufacturer ID `7D` (non-commercial) + `50 46` ("PF") + command. The text is characters 0x20–0x7E, `key=value` pairs joined with `;`, at most 240 bytes. Unknown keys are ignored. The FlowLocal-side implementation is in `flowlocal/src/fl_pf_monitor.h` and `fl_midi_bridge.h`.

| Direction | Bytes | Meaning |
|---|---|---|
| Laptop → FlowLocal | `F0 7D 50 46 01 F7` | Status request (every 2 s) |
| Laptop → FlowLocal | `F0 7D 50 46 10 52 43 F7` | **패널 연결 다시 잡기** ("Reconnect the panel") ('R' 'C') |
| Laptop → FlowLocal | `F0 7D 50 46 11 52 50 F7` | **패널 다시 켜기** ("Restart the panel") ('R' 'P') |
| Laptop → FlowLocal | `F0 7D 50 46 12 52 46 F7` | **FlowLocal 다시 켜기** ("Restart FlowLocal") ('R' 'F') |
| Laptop → FlowLocal | `F0 7D 50 46 13 43 48 <nn> F7` | `flx-mon3`: Wi-Fi channel ('C' 'H' followed by one value byte). `00` = pick automatically at start-up, `01`–`0D` = fix to that channel, `7F` = the next of 1, 6, 11 after the current channel. FlowLocal answers, saves the choice and restarts (USB after about 2 s, hotspot about 13 s, panel about 2 s later). The monitor sends "next" **as a number** instead of `7F` (so that two presses move only one channel, exactly the **다음 M번** ("next M") written on screen) |
| Laptop → FlowLocal | `BF 77 7F` | **소리 다시 맞추기** ("Re-sync the sound") (resync request, the same as the Live device's Resync) |
| FlowLocal → laptop | `F0 7D 50 46 02 <text> F7` | Status reply: `v fw up ap ch chm cl cm ps pip prs hd ra lp kn jt jm rx tx dr se to rj gp rr ud sr hi`; from `flx-mon2` also `rsn` (the reason for the last start: poweron, ext, sw, panic, int_wdt, task_wdt, wdt, deepsleep, brownout, sdio, usb, jtag, efuse, pwr_glitch, cpu_lockup, unknown), `bc` (number of starts since power was applied, including the current one), `why` (the reason it left before restarting itself: cmd12, web, bridge_hung, usb_wedged; empty if none), `ur` (number of times it re-attached USB by itself since start-up). FlowLocal side: `flowlocal/src/fl_recovery.h`. From `flx-mon3`, `chm` gains the value `manual` (a channel chosen with command 13), plus `cs=1:<score>,6:<score>,11:<score>` (the channel scores from the scan at the last start-up, lower is quieter; empty if there was no scan). The monitor reads `cs` leniently (it skips pieces it cannot read). Unknown keys are not used for diagnosis (if they are integers that only go up, they are logged) |
| FlowLocal → laptop | `F0 7D 50 46 03 <text> F7` | Command reply: `cmd=<10\|11\|12\|13>;ok=<0\|1>;msg=<short English text>` |

FlowLocal gives a status reply at most once every 200 ms, and accepts each command at most once every 3 s. Command 13 has 7 bytes inside the SysEx, so it fits FlowLocal's 8-byte receive buffer (`RX_MAX`). `flx-mon2` drops a SysEx of a length it does not know and does not answer (that is how the monitor recognizes "older firmware"). If the text would exceed 240 bytes, keys are dropped from the end (the monitor treats dropped keys as "unknown"). A normal `flx-mon1` reply is already 190–200 bytes, and `flx-mon2` appends `rsn bc why ur` after `hi`, so when the counters gain digits, these four keys are the first to be dropped (the monitor then leaves the start reason as "unknown"). If these keys are missing, as with `flx-mon1`, the monitor leaves the start reason as "unknown" and shows no alert.
